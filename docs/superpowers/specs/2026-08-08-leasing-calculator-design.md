# מחשבון ליסינג לעובדים — מסמך תכנון

**תאריך:** 2026-08-08
**סטטוס:** טיוטה לאישור

---

## 1. מה זו האפליקציה

כלי ווב בעברית שבו עובד מזין את הפרמטרים האישיים שלו (שכר, מרחק מהבית לעבודה, נסועה
שנתית צפויה, אפשרות טעינה בבית) ומקבל, עבור כל רכב בקטלוג הארגוני, את **העלות
הנטו האמיתית לכיס שלו** — לחודש, לשנה ולשלוש שנים — עם פירוק מלא של כל שקל.

הדגש אינו על "כמה עולה הליסינג" אלא על **"כמה זה עולה לי"**: אחרי השתתפות מעסיק,
אחרי זקיפת שווי שימוש למס, אחרי דלק או חשמל, ואחרי חריגה ממכסת הקילומטרים.

| מודל עלות | נטו אמיתי לתלוש + פירוק ברוטו לצידו. | רק המספר הנטו עונה על השאלה שהעובד באמת שואל. |

אין צורך בשמירת בחירות ברמת הארגון.

## 3. ארכיטקטורה

### 3.1 העיקרון המרכזי

```
מנוע החישוב לא יודע שקיים דפדפן.  הממשק לא מבצע חשבון.
```

`engine/` הוא TypeScript טהור, בלי React, בלי DOM, בלי תלויות. פונקציה אחת נכנסת,
אובייקט תוצאה יוצא. זה מה שמאפשר: בדיקות אמיתיות, השוואת רכבים (הרצה N פעמים),
ניתוח רגישות (סריקה על טווח), וייצוא לאקסל — כולם בחינם, בלי קוד נוסף.

### 3.3 צינור החישוב

```
{ vehicle, offer, employee, orgPolicy, taxRules, energyPrices, horizon }
      │
  ①  usage      → פילוח נסועה שנתית: ק"מ עבודה, ק"מ פרטי, שיעור נסיעה חשמלית
      │
  ②  energy     → צריכת ליטרים ו-kWh → עלות אנרגיה ברוטו
      │
  ③  lease      → דמי ליסינג בסיס, השתתפות עובד, דלתא שדרוג מעל תקציב הדרגה
      │
  ④  mileage    → ק"מ מעבר למכסה × תעריף חריגה, מופחת לחודשי
      │
  ⑤  subsidies  → השתתפות מעסיק בדלק, החזר היברידי/פלאגין, החזר טעינה  (שורות שליליות)
      │
  ⑥  tax        → שווי שימוש → נזקף לשכר → Δמס = f(שכר, מדרגות, ב״ל, נק׳ זיכוי)
      │
  ⑦  aggregate  → 1 חודש / 12 / 36 + פירוק מלא
      ↓
CalculationResult
```

כל שלב מחזיר `CostLine[]`. השלבים לא יודעים זה על זה — רק מקבלים קלט ומחזירים שורות.

### 3.4 הטיפוס שנושא הכל

```ts
type CostLine = {
  id: string
  labelHe: string
  category: 'lease' | 'energy' | 'tax' | 'mileage' | 'subsidy' | 'oneTime'
  monthlyAmount: number        // חיובי = יוצא מהכיס, שלילי = נכנס
  trace: {
    formulaHe: string          // "1,842 ק\"מ ÷ 14.2 קמ\"ל × 7.41 ₪"
    inputs: Record<string, number>
    sourceRef?: string         // "מחירון 2026-Q3 · שורה 41"
  }
}
```

השדה `trace` הוא הלב של האמון בכלי. הוא מה שהופך כל מספר במסך לניתן להסבר בלחיצה,
מה שמאפשר לפתור ויכוח מול HR, ומה שהופך באג בחישוב לניתן לאיתור תוך שניות.

### 3.5 מודל הנתונים — עיקרי הישויות

**Vehicle**
מזהה, יצרן, דגם, גרסה, שנה, `powertrain: ice | hybrid | phev | bev`,
מחיר מחירון, מדד ירוק/CO₂, קטגוריה, ואובייקט צריכה שנבדל לפי סוג הנעה:

```ts
type Consumption =
  | { kind: 'ice';    kmPerLiter: number; fuel: 'petrol95' | 'petrol98' | 'diesel' }
  | { kind: 'hybrid'; kmPerLiter: number; fuel: 'petrol95' }
  | { kind: 'phev';   evRangeKm: number; kwhPer100km: number
                      kmPerLiterHybridMode: number; fuel: 'petrol95' }
  | { kind: 'bev';    kwhPer100km: number; chargeLossFactor: number }
```

**LeaseOffer** — מפתח מורכב של `(vehicleId, termMonths, annualKmQuota)`.
דמי ליסינג חודשיים, השתתפות עובד, תעריף חריגה לק"מ, שירותים כלולים,
השתתפות עצמית בתאונה, אירועים חד-פעמיים (הפקדה, החזרה, החלפת צמיגים בשנה ג׳).

**EmployeeProfile** — שכר ברוטו, נקודות זיכוי, מרחק חד-כיווני מהבית,
ימי עבודה בחודש, נסועה פרטית שנתית, טעינה בבית (כן/לא + תעריף), טעינה בעבודה.

**OrgPolicy** — כתובה כ**נתון הצהרתי, לא כקוד**:

```jsonc
{
  "fuelParticipation": {
    "type": "distanceTiers",
    "tiers": [
      { "maxOneWayKm": 15, "employeeSharePercent": 40 },
      { "maxOneWayKm": 40, "employeeSharePercent": 25 },
      { "maxOneWayKm": null, "employeeSharePercent": 10 }
    ]
  },
  "powertrainRebate": { "hybrid": 150, "phev": 300, "bev": 400 },
  "homeChargingReimbursement": { "type": "perKwh", "rate": 0.55, "monthlyCapKwh": 250 },
  "budgetByGrade": { "A": 1900, "B": 2400, "C": 3100 },
  "upgradeChargeRate": 1.0
}
```

הצורה הזו היא הסיבה שהאפליקציה תשרוד שינויי מדיניות. כשהארגון משנה מדרגה —
עורכים JSON. אף שורת קוד לא זזה.

**TaxRules** — מגורסא לפי שנה. לשנת 2026: שיעור המודל הליניארי 2.48% ממחיר
המחירון, תקרת מחיר מחירון 596,860 ₪, הפחתות חודשיות קבועות של 560 ₪ להיברידי,
1,130 ₪ לפלאג-אין ו-1,350 ₪ לחשמלי מלא; מדרגות מס 2026 המורחבות (20% עד 19,000 ₪,
31% עד 25,100 ₪); ערך נקודת זיכוי 242 ₪. כל אלה **נתונים בקובץ**, לא קבועים בקוד,
ומלווים בשדה `sourceUrl` ו-`effectiveFrom`.

## 4. חמש נקודות שיכריעו את דיוק הכלי

אלה מקומות שבהם מחשבוני ליסינג נכשלים בדרך כלל. הן מטופלות מפורשות בתכנון.

**① מקדם הנסיעה החשמלית ב-PHEV.**
העלות של פלאג-אין משתנה פי שניים לפי מה שאדם באמת נוסע על חשמל. זה תלוי בטווח
החשמלי, במרחק החד-כיווני, בקיום עמדה בעבודה ובמשמעת טעינה. **ההחלטה: לא להסתיר
את זה מאחורי הנחה.** המנוע יגזור ברירת מחדל מהטווח ומהמרחק, והממשק יציג אותה
כמחוון שהעובד רואה ויכול להזיז — עם הצגה מיידית של ההשפעה.

**② מס שולי, לא מס אפקטיבי.**
שווי השימוש נזקף *מעל* השכר, ולכן ממוסה בשיעור השולי, ועלול לדחוף למדרגה הבאה.
החישוב חייב להיות `Δ = tax(שכר + שווי) − tax(שכר)`, לא `שווי × אחוז`. גם ביטוח
לאומי הוא פונקציית מדרגות עם תקרה — קפיצה, לא קו.

**③ חריגת ק"מ היא מדרגה, לא שיפוע.**
הבחירה בין מכסת 20,000 ל-25,000 ק"מ היא לעיתים קרובות כל ההחלטה. הממשק יציג
במפורש היכן נמצא "הצוק" ביחס לנסועה החזויה של העובד.

**④ שלוש שנים ≠ חודש כפול 36.**
הפקדה בתחילה, החלפת צמיגים בשנה ג׳, חיובי החזרה, השתתפות עצמית. `horizon.ts`
מטפל באירועים חד-פעמיים הממוקמים בחודש מסוים.

**⑤ מחירי אנרגיה הם תרחיש, לא קבוע.**
מחיר הדלק והחשמל נכנסים כפרמטר עם ברירת מחדל ומסך רגישות — לא כמספר קשיח.

## 6. מסכים

1. **פרופיל** — הגדרה חד-פעמית, שישה שדות, נשמר מקומית.
2. **קטלוג** — כרטיס לכל רכב, ועליו **העלות החודשית שלך**, לא מחיר המחירון.
   סינון לפי סוג הנעה, תקציב, קטגוריה. זו התובנה המרכזית: לפרסן את הקטלוג מיד.
3. **דף רכב** — תמונות, מפרט, ופירוק העלות עם לשוניות חודש / שנה / 3 שנים.
4. **השוואה** — עד ארבעה רכבים זה לצד זה, עם הדגשת ההפרש בלבד.
5. **רגישות** — "מה אם אסע 5,000 ק"מ יותר?", "מה אם הדלק יעלה 15%?".

## 7. אסטרטגיית בדיקות

עיקר מאמץ הבדיקה הולך למנוע, לא לממשק.

- **יחידה** לכל מודול במנוע, כולל מקרי קצה: תקרת מחיר מחירון, גבולות מדרגות מס,
  תקרת ביטוח לאומי, נסועה אפס, חריגה שלילית.
- **תרחישי-זהב**: כל תרחיש הוא זוג `input.json` / `expected.json`, שנגזר מהאקסל
  הקיים. זו רשת הביטחון שמאפשרת לשנות את המנוע בלי פחד.
- **ולידציית סכמה** רצה ב-CI על כל קובץ נתונים — מחירון שבור נתפס לפני deploy.
- הממשק נבדק בבדיקות עשן בלבד. אין בו לוגיקה לבדוק.

## 8. תמונות הרכבים — סוגיה שדורשת הכרעה

תצלומי רכבים מאתרי יצרנים ויבואנים **מוגנים בזכויות יוצרים ואינם שלך**.
שימוש פנים-ארגוני בכלי השוואה הוא נוהג מקובל ובסיכון נמוך, אך אינו רישיון.

התכנון תומך בשתי הדרכים במקביל: לכל רכב תיקיית נכסים עם `credits.json` הנושא
מקור וקרדיט, ואילוסטרציה וקטורית כברירת מחדל כשאין תמונה מאושרת. ההמלצה היא
לבקש מהיבואן ערכת תמונות רשמית — זו בקשה שגרתית שכמעט תמיד נענית, והיא מייתרת
את הסוגיה כולה.

## 9. מה בכוונה לא נכנס

מערכת הרשאות והתחברות. אישורי מנהלים וזרימת בקשות. דוחות HR מרוכזים.
אפליקציה נייטיב. תמיכה רב-לשונית. השוואה מול רכב פרטי קיים.
כל אחד מאלה מוסיף שרת, מסד נתונים או שכבת אבטחה — ואף אחד מהם אינו נדרש
כדי לענות על השאלה "כמה זה עולה לי".
